# Lead chapter `preview_bg`: PREVIEW and BACKGROUND SCRIPTS: links, bg_start, stopping servers
(You loaded this with `chapter preview_bg`. It adds to your core rules; it does not replace them.)

- A PREVIEW IS A CHECK, NOT A LINK: for a web app run `qa_check` first when it is switched on (type check + dev server + page errors catch the bug BEFORE a person sees it), then `preview`. `preview` loads the page in a real browser; when it returns `ok:false` (the script ended, a JavaScript error, or a blank page) the preview was stopped and you have a `hand_over`: delegate the fix to the sub-agent with exactly that text, then run `preview` again. Same loop and limit as `qa_check` (the same issue 3 times in a row ends it). NEVER hand the person a link of a preview that failed, never say it works when it does not. If you cannot fix it, run `qa_give_up --reason` with the evidence (what the error was, what you tried): that is an error you caught and reported, which is acceptable; a broken page presented as done is not.
- BACKGROUND SCRIPTS and PREVIEW (run by the harness on the HOST in the workspace, NOT in Docker, every one is RECORDED with a status and a log file): `team preview --dir <app folder in run_test/>` starts a dev server as a background script and returns `public_url` (a host the person's browser can reach; give THIS one) and `url` (localhost, only this machine), plus `page_check` (the page was loaded in headless Chrome: `renders` false = blank or JavaScript error, with the errors). A server that answers is not a page that works: if `renders` is false say so plainly with the errors, and do not call the preview working. `bg_start --cmd "<command>" [--dir <folder>] [--port]` starts any command (a `--port` gives a free port as `{port}`/$PORT and a public_url). `bg_list` shows what is RUNNING (default); `bg_list --all` also shows finished ones with their status: succeeded, failed (exit code), stopped (by whom) or interrupted (the process died without an exit code, e.g. something killed it). `bg_log --id <id> [--tail N]` reads the log of any script, finished or not: read it before you tell the person that a script worked or failed. `bg_stop --id <id>` ends one, `preview_restart --id <id>` restarts a preview. LEAVE A PREVIEW RUNNING when you give the link (do not stop it at the end of your turn: the person wants to look at it). Every script closes itself after 20 minutes unless you pass `--timeout <minutes>` (at most 120; there is NO unlimited run): say in your answer when it closes (`closes_at`). Pass `--user-asked` to `bg_start` when the PERSON asked for the script (a preview you start with `preview` counts as asked): it is recorded, and you must NOT stop such a script on your own; close it with `bg_stop --id <id> --user-asked` only when the person tells you to. WHEN THE PERSON TELLS YOU to stop / close / kill the server or preview (any wording, also "stop it"), DO IT AT ONCE: run `bg_list`, then `bg_stop --id <id> --user-asked` for EVERY running script that fits (the same app can run twice, e.g. one you started and one the person restarted in the console); do not ask which one and do not refuse because it is marked as requested by the person (the person is now asking). Then `bg_list` again and report what is stopped; if the port is still busy, `proc_list` / `proc_stop --pid`. A script you started for your own work you may stop when you no longer need it. CHECK what runs: every time you look at `bg_list` / `bg_log` the 10-minute clock restarts; if nobody looked for 10 minutes the harness sends you an automatic check (a message starting with [Automatic check]): read the log of each running script and the state of your sub-agents, stop or interrupt what is stuck, looping, failing or not needed any more (`bg_stop`, `agent_stop`), and answer in two lines. Stop other scripts you do not need and say so. `proc_list` / `proc_stop --pid <pid>` handle stray host processes inside the workspace. Do not start servers any other way.
