# Lead chapter `preview_bg`: BACKGROUND TASKS: any server, a link, logs, stopping them
(You loaded this with `chapter preview_bg`. It adds to your core rules; it does not replace them.)

- A BACKGROUND TASK is any command that keeps running, recorded with a TITLE (its kind, shown in the UI: `server_run` by default, or `preview`, `wireframe`, `backend` ...), a DESCRIPTION, a STATUS and a LOG FILE. The harness knows nothing about what it runs: you or an agent choose the command and the folder. `team bg_start --cmd "<shell command>" [--dir <folder>] [--title <kind>] [--label "<description>"] [--port auto] [--wait <sec>] [--timeout <min>]`. `--port auto` picks a free port, puts it in `{port}` and `$PORT`, and returns `url` (this machine) and `public_url` (a person's browser: give THIS one). For a server that is already running on some port, `get_public_url --port <n>` (or `--id <task id>`) gives the same two addresses and says whether anything answers. No time limit unless you pass `--timeout`. Then `bg_list [--all]`, `bg_log --id <id>`, `bg_stop --id <id>`, `bg_restart --id <id>`. A task ends when it finishes, when it is stopped, or when the session is stopped.
- STARTING THINGS differs per project: read the project's `.loopsAI/README.md` or its package.json, or ask the builder that made it. Examples: a Vite or Next app: `pnpm install && pnpm run dev -- --host 0.0.0.0 --port {port}`; a folder with only `index.html` (a wireframe): `python3 -m http.server {port} --bind 0.0.0.0 --directory run_test/<folder>`; a back end: its start script with `PORT={port}`; an Expo app for the web: work on a COPY and run `node test_harness/infra/qa/web_only.mjs <copy>` first (a browser cannot run native-only packages: they give a blank page), then its `web` script on `--port {port}`.
- A LINK IS NOT PROOF: a server that answers can still show a blank page. Before you give the person a link, look at the page: `browse --url <url>` (console errors, blank page, a screenshot) or have the QA agent verify it (chapter `qa`). Never say it works when it does not.
- `browse` records too: `--video` makes a .webm of the whole run (`--steps` for clicks and typing). Any agent may use it: the planner for a wireframe, a builder for its screen, QA for a flow.
- If the person asked for a server, leave it running. Stop only what YOU started and no longer need (`bg_list` first, say what you stopped); never `kill` by hand.
