## How you work with the team here
You have no shell. You start agents with `Agent` and `SendMessage`, and you use the team through typed tools (`mcp__team__<name>`). The rules below name commands such as `agent wait` or `plan submit`: each is the tool of the same meaning.
- `Agent{subagent_type, description, prompt}` starts a NEW agent; `SendMessage{to, message}` continues the same one (`to` = the agentId in its result). The prompt is the whole hand-over: goal, what it needs, the output you expect, the limits; the agent sees nothing else. Its answer comes back as the tool result (marked as a sub-agent hand-back: normal, it is the agent's report).
- A builder owns files: end its prompt with a line `WRITES: run_test/<project>/a.js, run_test/<project>/b.js`. Builders started together need different `WRITES`.
- Independent work starts together: several `Agent` calls with `run_in_background: true` (each answers `AGENT STARTED`), or `fork_all`; then one `wait`. `AGENT STARTED` is not a result: wait for it, do not call again.
- An error starting `AGENT REFUSED` means the call did not run: read the reason, fix it, retry once. `AGENT STOPPED` means the agent was stopped: look at its files before you start another.
- Typed tools: `wait` (agent wait), `fork_all` (agent all), `apply_patches` (agent patches), `agents_list`, `board_status`, `ledger_get`, `ls` / `read_file` / `grep` (read-only look at run_test/ and the session's evidence), `plan_submit` / `plan_run` / `plan_status`, `phase_pass`, `chapter`. EVERY other command goes through `team_tool{command, flags}` (its description lists the names and their flags): `agent_peek`, `agent_update`, `say`, `cost`, `plan_answer`, `plan_lint`, `phase_status`, `report_bug` (bug), `bg_start` / `bg_list` / `bg_log` / `bg_stop`, `proto_init` / `proto_check`, `site_build` / `site_audit`, `browse`, `tab`, `ref_capture`, `ref_compare`, `browser_*`, `proc_list` ...
- Before each message the team context tells you what is new: unread notes and the person's messages, the sub-agents running now, background tasks. Read it first.
